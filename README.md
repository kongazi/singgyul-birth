# SINGGYUL MARKET 🍊

- GitHub: https://github.com/kongazi/singgyul-birth
- Vercel 프로젝트: https://vercel.com/kongazis-projects/singgyul-birth
- `main` 브랜치에 push하면 Vercel에서 자동으로 프로덕션을 배포합니다.
- 프로덕션은 Neon의 `singgyul-birth-db` 무료 데이터베이스를 사용합니다. 로컬 개발의 편지 파일은 자동으로 업로드하지 않습니다.

Next.js 생일 마켓. 100귤로 굿즈를 고르고 편지와 함께 접수하거나 편지만 보낼 수 있습니다.

## 로컬 실행

```sh
npm install
node scripts/setup-admin.mjs
npm run dev
```

마켓: http://localhost:3000 · 관리자: http://localhost:3000/admin (`/addmin`도 연결)

관리자 비밀번호는 `.env.local`의 `ADMIN_PASSWORD`입니다. 설정 스크립트는 무작위 비밀번호와 세션 키를 생성하며 기존 값을 바꾸지 않습니다. 파일은 Git에서 제외됩니다. 환경변수 변경 시 서버를 재시작하세요.

## 편지 보관과 접근 제한

- 편지와 검토 기록은 서버에만 저장합니다. 일반 사용자의 API 응답, 주문내역, JSON 다운로드에는 편지 본문이 없습니다.
- 편지 초안은 영구 저장하지 않습니다. 작성 도중 새로고침하면 사라집니다.
- 브라우저에는 장바구니와 본문 없는 접수 내역만 남깁니다.
- 관리자 페이지와 조회·수정 API는 서버에서 서명 및 세션 유효성을 검사합니다. 화면 조작으로 인증을 우회할 수 없습니다.
- 세션은 HttpOnly / SameSite=Strict 쿠키이며 프로덕션에서는 Secure가 적용됩니다. 4시간 뒤 만료되고 로그아웃 시 서버에서 무효화됩니다. 비밀번호나 세션 키를 바꾸면 기존 세션도 무효화됩니다.
- 변경 API Origin 검사, 로그인 시도 제한, 요청 크기 제한, 서버 측 가격·수량·글자 수 검증, no-store 응답을 적용했습니다.
- 작성자의 입력 내용과 자신의 전송 요청, 이미 다운로드한 파일, 로그인한 관리자의 개발자 도구까지 숨길 수는 없습니다. 인증되지 않은 방문자가 서버에 보관된 편지를 읽지 못하도록 보호합니다.

로컬 개발에서는 프로젝트의 `.private-data/`에 저장합니다. public 폴더 밖이며 Git에서도 제외됩니다. 이 컴퓨터의 파일 접근 권한을 가진 사람은 읽을 수 있습니다.

## 이전 브라우저 데이터

이전 버전의 브라우저 편지는 마켓 접속 시 서버로 이전합니다. 모든 접수가 성공한 뒤 기존 본문 저장본을 제거합니다. 실패하면 데이터 손실을 막기 위해 이전 기록을 유지하고 경고합니다. 관리자는 로그인 시 기존 검토 메모와 상태도 이전합니다. 이전 완료 전 기존 localStorage는 개발자 도구에 남아 있을 수 있습니다. 이전 다운로드 파일과 이미 열린 네트워크 로그는 소급 삭제하지 않습니다.

## 관리자 기능

- 굿즈 목록, 선택 수량, 포함된 주문 조회
- 편지 전문 검색, 확인 여부 및 전달 분류 필터
- 미확인 / 확인 완료, 미분류 / 전달 가능 / 보류 / 전달 불가, 관리 메모 저장
- 확인 완료인 편지만 전달 가능으로 설정
- 전달 가능 편지 JSON 내보내기 (관리 메모 제외, 실제 자동 발송은 아님)

## Vercel 배포

다음 서버 전용 환경변수를 설정하세요. `NEXT_PUBLIC_` 접두사를 붙이지 마세요.

| 변수 | 용도 |
| --- | --- |
| ADMIN_PASSWORD | 16자 이상 비밀번호, 무작위 32바이트 권장 |
| ADMIN_SESSION_SECRET | 32자 이상 무작위 세션 서명 키 |
| DATABASE_URL | TLS를 지원하는 PostgreSQL 연결 문자열 (Neon/Supabase 등) |

최초 요청에서 `singgyul_private` 테이블을 생성하므로 DB 연결 계정에 해당 권한이 필요합니다. 편지, 검토 기록, 관리자 세션, 로그인 횟수를 DB에 보관합니다. DB 자격증명은 서버에만 설정하세요.

Vercel 및 프로덕션에서 DATABASE_URL이 없으면 접수와 로그인은 실패하도록 했습니다. 임시 파일 저장으로 배포 후 편지가 유실되지 않게 하기 위함입니다. 실제 DB 연결과 Vercel 배포는 별도 진행이 필요합니다. 로컬 `npm run dev`만 파일 저장소를 사용합니다.
